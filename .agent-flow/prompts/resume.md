# Prompt: Продолжить работу

Не полагайся на память предыдущего чата.

1. Прочитай `AGENTS.md`, `PROJECT.md`, `POLICY.md`, `WORKFLOW.md`.
2. Запусти `flow status`, выбрав `flow.ps1` для PowerShell или `flow` для Bash
   по правилу из `AGENTS.md`, и найди задачу, указанную пользователем.
   Если активных несколько и задача не названа — попроси выбрать.
3. Прочитай все Markdown-файлы выбранной task-папки и связанные decision records.
4. Сверь записанное состояние с `git status`, `log` и полным diff от baseline.
   Staged-файлы и commits человека нормальны. Обнови наблюдаемое состояние и
   останавливайся только при изменениях вне scope или реальном конфликте.
   Для ещё не принятого слайса проверь наличие и актуальность независимого
   ревью. Если проверяемое содержимое изменилось после отчёта, повтори
   ревью после завершения разрешённых исправлений и проверок.
   Не повторяй ревью уже принятых неизменённых слайсов.
   Записи о выполненном ревью не заменяют человеческое принятие.
5. Дай резюме не длиннее 12 пунктов: goal, approved decisions, completed slices,
   evidence, текущий diff, blockers, residual risks и следующий gate.
6. Сначала перенеси ещё не записанное явное решение пользователя из текущей
   сессии в журнал согласований и обнови state в `brief.md`/`progress.md`.
   Если решение уже покрывает нужный gate, не запрашивай его повторно.
   При `WAIT_*` жди только отсутствующее решение; учитывай его область и
   условие коммита перед следующим slice. Не придумывай approval по памяти.
7. Если задача старого формата содержит `review.md`, не используй его как
   вердикт. При переходе к финализации создай `final-review.md` по актуальному
   шаблону и следуй `prompts/finalize.md`.
