# Передача контекста

Цель этапа — оставить у разработчика рабочую модель изменения, а не проверить
его экзаменом. Агент кратко заполняет `handoff.md` по реальному коду и задаёт
один вопрос: достаточно ли контекста или нужно отдельно разобрать поток
выполнения либо диагностику.

## Обычные задачи (`QUICK`, `GUIDED`, `MECHANICAL`)

Разработчик может ответить, что контекста достаточно. В этом случае отдельный
опрос, проверка знаний и повторный пересказ не нужны.

По запросу агент проводит один из разборов:

- поток: точка входа → решения → состояние/побочные эффекты → результат;
- диагностика: наблюдаемый симптом → логи/метрики → вероятные места ошибки →
  локализация и откат.

## Критические задачи (`CRITICAL`)

Перед закрытием обязателен короткий разбор диагностики и отката, даже если
разработчику уже понятен основной поток. Агент показывает:

- как проявятся основные ошибки;
- где искать подтверждение причины;
- как ограничить последствия;
- как отключить или откатить изменение;
- какие действия необратимы или требуют отдельного решения.

Этап не содержит вопросов с оценкой и не требует от разработчика пересказывать
код. Решение о достаточности контекста всегда остаётся за человеком.
